# BarClode Battler

**BarClode Battler** is a browser remake of Epoch's 1991 **Barcode Battler II** handheld. The name is a nod to Claude, which builds it. You type or scan an EAN barcode and it becomes a warrior, wizard, item or enemy card. Then the cards fight.

**Play:** https://kelu124.github.io/barcodebattler/

It works on a phone, needs no account or server, and runs offline once the page has loaded.

## Modes

| Menu | Original | What it is |
|------|----------|------------|
| VS CPU | C0 | Your card against a CPU-played card (yours to enter, or a random enemy of similar strength) |
| 2 PLAYERS | C0 | Two cards, one device, pass and play |
| STORY | C1 | Two heroes go through the worlds, beat enemies, collect keys, and get a passcode at each stage clear |
| ENEMY CARDS | C2 | Fight enemy cards (typed, scanned or picked from the book) to win stat rewards and level passcodes |
| SET STORIES | — | A short story built from one official card set: its heroes, its enemies, its items |

## Features

- **Any EAN-13 / EAN-8 barcode** becomes a card. The conversion is deterministic, so the same barcode gives the same card on every device.
- **Camera scanning** uses the native `BarcodeDetector` when the browser has it, and otherwise a pinned ZXing build. Typing the barcode always works.
- **Card book** with all 934 official BB2-compatible cards from 24 sets. Japanese cards have English names, each marked as official or translated.
- **My cards**: save the cards you like (only the barcode and name are stored, in `localStorage`).
- Retro green-LCD handheld look, segment digits and WebAudio sounds, with a mute button.

## Run it locally

```bash
npm run serve        # python3 -m http.server 8737 -d docs
# open http://localhost:8737/
npm test             # engine tests (node --test, Node 22+)
```

There's no build step and no dependencies to install. The site is plain HTML, CSS and ES modules in `docs/`.

Two URL flags help when developing: `?debug` logs battle events to the console and `?fast` runs animations 20× faster for automated browser tests.

## How it's built

```
docs/                 GitHub Pages root (pushing to main publishes it)
  src/engine/         pure game logic: barcode → card, fusion, battles, passcodes, story, no DOM
  src/ui/             screens, LCD, card book, scanner, sound
  data/cards.json     official card list, generated by tools/import-maeyomi.mjs
tests/                node --test suites for the engine
tools/                card-list import + English name translations
notes/                design notes (for example, which 8-bit hardware quirks we don't reproduce)
```

The engine and the UI are kept separate so that game rules can be tested without a browser. Battle randomness goes through a seeded RNG, so fights replay the same way in tests.
